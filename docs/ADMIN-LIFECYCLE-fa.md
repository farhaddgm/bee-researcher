# قرارداد چرخهٔ رابط ادمین

افزونه‌های ادمین نباید برای اجرای منطق بعد از بارگذاری/زبان/صفحه، تابع global قبلی را بگیرند و چندبار بازنویسی کنند. از `BeeAdminLifecycle.register(owner, names, hooks)` استفاده کنند. `owner` ثابت و یکتا است؛ ثبت دوباره جایگزین می‌کند. تابع dispose ثبت قدیمی، ثبت جدید همان مالک را حذف نمی‌کند.

- `before`: آماده‌سازی هم‌زمان، پیش از تابع اصلی.
- `after`: فقط در موفقیت؛ برای تابع async، تکمیل hookهای async نیز در بازگشت await می‌شود.
- `settled`: پس از موفقیت یا شکست؛ شکست اصلی بازپرتاب می‌شود.
- رفتار پیش‌فرض scoped است: اگر کاربر/پروژه تغییر کند، callback تکمیلِ درخواست قدیمی اجرا نمی‌شود. hook سراسریِ پاک‌کردن حالت busy می‌تواند آگاهانه `scoped:false` باشد.
- hook نباید در انتظار `loadAll`، خودش دوباره همان `loadAll` را صدا بزند؛ این بازگشت به درخواست مشترک می‌تواند چرخهٔ انتظار ایجاد کند. تازه‌سازی دادهٔ پنل باید تابع مستقل داشته باشد.
- خطای پنل جانبی در پروفایل شمارش می‌شود، نه اینکه خطای اصلی بازخوانی پنهان شود. نگهداری آرگومان، exception خام، شناسهٔ کاربر/پروژه، URL، متن خبر یا کلید در diagnostics ممنوع است؛ حداکثر ۱۰۰ نمونه نگهداری می‌شود.

نصب facade پس از پایهٔ سازگاری و کنترلرهای احراز هویت انجام می‌شود تا ترتیب parser و اولین نمایش تغییر نکند. از آن پس کنترلرهای مهاجرت‌شده تابع‌های lifecycle را بازنویسی نمی‌کنند. facade باید idempotent باشد. کنترلرهای قدیمی پشتیبانی در فایل تاریخی باقی می‌مانند ولی در HTML سرو نمی‌شوند.

راه‌اندازی workspace اکنون یک پیاده‌سازی در `admin_workspace_bootstrap.js` دارد؛ loader آن را در همان دارایی هم‌زمانِ هسته جایگذاری می‌کند، نه در یک درخواست دیرهنگام جدید. پاسخ فهرست دستیارها قبل از هر نمایش، دوباره با کاربر و پروژهٔ فعلی تطبیق داده می‌شود. انتخاب اولین پروژهٔ مجاز یک تغییر معتبر scope است؛ علامت نتیجه فقط وقتی پذیرفته می‌شود که هنوز با scope جاری یکسان باشد. بنابراین اولین ورود بدون refresh اضافی مدل و تنظیمات را پر می‌کند، ولی پاسخ دیررسِ حساب قبلی در حساب جدید نمایش داده نمی‌شود.

کنترلر ظاهری `backoffice_ui.js` بین Admin و User مشترک است. استفادهٔ آن از رجیستری Admin اختیاری است؛ پرتال User نباید برای tooltip، toast یا آواتار مجبور به بارگذاری زیرسیستم Admin باشد. این استقلال با اجرای واقعی کنترلر در VM بدون هیچ global ادمین و با آزمون کامل مرورگری User کنترل می‌شود.

آزمون‌ها شامل خطای sync/async، حفظ مقدار بازگشت، GC اجباری، عوض‌شدن actor، پاک‌شدن درخواست مشترک در موفقیت/شکست، dispose، عدم انباشت hook، عدم نشت پشتیبانی به صفحهٔ دیگر و رقابت کش با mutation است. مهاجرت پایهٔ قدیمی باید جداگانه با همین قرارداد و آزمون تصویری/عملکردی انجام شود؛ حذف ظاهری نام فایل یا افزایش skip در CI پذیرفته نیست.
