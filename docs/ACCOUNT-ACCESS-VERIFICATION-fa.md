## محیط

۴. API/SQL حساب‌ها: ورود رمزی با ایمیل و نام قدیمی، روش‌های PASSWORD/GOOGLE/BOTH، Gmail نرمال‌شده، مالک محفوظ، subject گوگلی پایدار، grant بدون حساب تکراری، ورود حساب نامجاز/غیرفعال رد، self-service بدون ارتقای نقش، CSRF، جداسازی User/Admin و scoped assistants.

۶. نشست: Admin با cookie پایدار و سقف شناور ۳۰ روز؛ User با مرز ثابت ۰۲:۰۰ سرویس. تغییر روش/وضعیت/مجوز هر دو نشست را فوراً باطل می‌کند. خروج Admin نشست مستقل User را نمی‌بندد. توکن User به‌جای Admin پذیرفته نمی‌شود.

۸. **رگرسیون User**: ورود، حفظ تنظیمات، اعلان مرورگر ساختگی/قابل مشاهده و محدودبودن جهت متن به کارت خبر؛ صفر uncaught.

۹. **رگرسیون پشتیبانی**: ساخت تیکت، پاسخ مالک، متن immutable، بسته‌شدن، focus کیبورد، منع User پیش‌فرض، اعطای صریح و محدودیت دستیار؛ صفر uncaught.

## اصلاحاتی که تست پیدا کرد

- APIهای قدیمی نباید حساب Google-only را صاحب رمز داخلی کنند.
- ویرایش مشخصات شخصی نباید به نقش مدیر پروژه نیاز داشته باشد.
- متن دکمهٔ ورود عربی در عرض ۳۲۰ از کارت بیرون می‌زد؛ فرم‌های هر دو پرتال یک قرارداد responsive گرفتند.
- listener قدیمی زبان ممکن بود مودال را با تغییر مجدد همان زبان ببندد؛ rebuild فقط با تغییر واقعی locale انجام می‌شود.
- namespace constraint در rollback باعث نام دوباره‌پیشوندخورده می‌شد؛ از `op.f` استفاده شد.
- حفظ نشست‌های بدون نوع پرتال امنیت جداسازی را نقض می‌کرد؛ migration همهٔ نشست‌های قدیمی را یک‌بار باطل می‌کند.

## مواردی که این گزارش تأیید نمی‌کند

ورود به Google واقعی، تنظیم OAuth در Google Cloud، بازبینی مستقل انسانی ترجمه‌ها، GitHub CI، اسکن کامل OS image/امضای registry و انتشار production در این مرحله انجام نشده‌اند. روی سرویس زنده OAuth Researcher موجود نبود؛ نسخهٔ زنده عمداً دست‌نخورده مانده است. Contenter و سایر سرویس‌ها نیز تغییری نکرده‌اند. فعال‌سازی واقعی مطابق [راهنمای مالک](ACCOUNT-ACCESS-fa.md) پس از تأمین امن سه تنظیم OAuth انجام می‌شود.
