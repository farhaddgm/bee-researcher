# برنامه توسعه و پذیرش گفتگوی صوتی ElevenLabs

تاریخ: ۱۱ اکتبر ۲۰۲۶. **دامنه اصلی E01 و E02 در نسخه 3.45.0 توسعه داده شده است؛ شروط وابسته به حساب واقعی E00 و کیفیت/دستگاه واقعی هنوز باز هستند.** جدول‌ها معیار پذیرش باقی می‌مانند و توسعه کد به‌تنهایی به معنی تأیید کیفیت سرویس واقعی نیست. E03 Agents اختیاری خارج از این نسخه است. راه‌اندازی، آزمون حساب و محدودیت‌های عملی در [راهنمای عملیات](ELEVENLABS-VOICE-OPERATIONS-fa.md) آمده‌اند.

ورودی محصول: [طرح و ۱۵ ایده](ELEVENLABS-VOICE-PROPOSAL-fa.md). قراردادها: [طرح فنی](ELEVENLABS-VOICE-TECHNICAL-DESIGN-fa.md).

## مرحله صفر: آزمون قابلیت حساب و تثبیت قرارداد

| وظیفه | خروجی | شرط پایان |
|---|---|---|
| E00.1 حساب و secrets | نام region/plan، قابلیت logging/retention، key کم‌اختیار در secret store، نرخ/سقف و مرجع قیمت | key در مخزن/مرورگر/لاگ/گفتگوی کاربر نباشد؛ هزینه پایلوت محدود و از قبل مشخص باشد |
| E00.2 ماتریس مدل | آزمایش STT، HTTP TTS، timing و TTD با voiceهای انتخابی برای هر زبان | مشخص شود account/endpoint دقیقاً کدام مدل را قبول می‌کند؛ اختلاف v3/v4 مستند با نتیجه واقعی تعیین تکلیف شود |
| E00.3 نمونه فارسی | مجموعه مصنوعی شامل عدد، تاریخ، نام شرکت، مخلوط فارسی/انگلیسی، مکث، نیم‌فاصله و نویز | شنیدن و transcript روی دستگاه واقعی؛ نتیجه کیفیت/تأخیر ثبت شود و فقط مدل قابل استفاده انتخاب شود |
| E00.4 فرمت و مرورگر | ضبط PCM، sample rate واقعی، پخش/دانلود فرمت منتخب در Chrome/Edge/Firefox/Safari و iOS/Android | نیاز gesture، permission و محدودیت پخش chunk در هر مرورگر مشخص باشد؛ شکست به متن قابل استفاده برسد |
| E00.5 محل نگهداری | volume خصوصی، کلید مستقل صوت، quota، staging TTL، backup و deletion policy | مسیر/کلید Report استفاده نشود؛ رفتار حذف و بازیابی قابل آزمایش باشد |

این مرحله با endpointهای رسمی و حساب واقعی انجام خواهد شد، اما نمونه‌ها اطلاعات پروژه واقعی ندارند. سند فعلی بدون API key و بدون فراخوانی پولی تهیه شده است. قرارداد مورد آزمایش از [STT Realtime](https://elevenlabs.io/docs/api-reference/speech-to-text/v-1-speech-to-text-realtime)، [HTTP TTS](https://elevenlabs.io/docs/api-reference/text-to-speech/stream) و [TTD reference](https://elevenlabs.io/docs/api-reference/text-to-dialogue/ttd-websocket) گرفته شود.

| E01.6 رابط گفتگو | E01.3، E01.4 | سه حالت متن/صوت/هم‌زمان، میکروفن و consent، انتخاب voice/language مجاز، player؛ ترتیب Discuss زیر Summarize حفظ شود |
| E01.7 ذخیره صوت | E01.5، E01.6 | پنجره دامنه AI/کامل، عنوان، snapshot، complete/partial و تأیید نگهداری متن؛ recovery بعد از قطع شبکه بدون تکثیر فایل |
| E01.8 حافظه صوتی | E01.7 | کارت پروژه، متن، player، دانلود همان فایل، فیلتر و pagination؛ پس از ورود دوباره قابل بازیابی باشد |
| E01.9 حذف و خروج | E01.5، E01.7 | tombstone/outbox، رقابت save/delete/close، تأیید حذف صوت در unsave، بستن بدون ذخیره، حذف حساب/پروژه/خبر و پاکسازی orphan |
| E01.10 مصرف و عملیات | E01.2، E01.9 | تفکیک STT/TTS/LLM و تخمین/نهایی، محدودیت storage، metrics بدون محتوای خصوصی، deployment drain |

بدون E01.7 و E01.8، «ذخیره صوت» تحویل‌شده محسوب نمی‌شود. فایل قابل دانلود از همان byteها، اتصال به متن/منابع، بازپخش بدون TTS تازه، و ضبط واقعی صدای کاربر برای دامنه کامل باید با هم کار کنند. تولید فایل صرفاً از متن به‌عنوان «گفتگوی ضبط‌شده کامل» پذیرفته نیست.

## مرحله دو: تجربه پیوسته و ابزارهای صوتی

پس از پذیرش مرحله یک، E02.1 adapter TTD و streaming متن، E02.2 interruption و ثبت بخش شنیده‌شده، E02.3 ارسال خودکار opt-in پس از مکث، E02.4 انتخاب بازه/نوبت و bookmark، E02.5 واژه‌های تلفظ منتخب، و E02.6 گزارش روزانه با همان adapter اجرا شوند. هر کدام مستقل پشت flag و با سقف هزینه باشند؛ کیفیت و سازگاری مرحله صفر دوباره سنجیده شوند.

هدف پیشنهادی تجربه پایلوت: median پایان سؤال تا شروع پخش ≤۳ ثانیه برای حالت streaming و متن مصنوعی کوتاه؛ صدک ۹۵ نیز گزارش شود. این هدف Bee است و تضمین ElevenLabs یا شرط اثبات‌شده امروز نیست. معیار توقف با دکمه/قطع‌کردن: صدای محلی حداکثر در ۵۰۰ ms متوقف شود؛ زمان قطع upstream جدا اندازه‌گیری و با سقف سروری کنترل شود.

## مرحله سه اختیاری: ElevenAgents

Agent خصوصی با Custom LLM bridge فقط در صورت نیاز به گردش مکالمه managed ارزیابی شود. وظایف مستقل: provider-session binding سروری، token یا signed URL، کنترل override، handshake مجاز، context منتخب، تکرار callback بدون LLM دوباره، webhook معتبر، import صوت، هزینه و remote deletion.

مرورگر فعلی vanilla JavaScript است؛ SDK سازگار JavaScript و bundle محلی pin شود و صرفاً برای این اتصال React اضافه نشود. [SDK JavaScript](https://elevenlabs.io/docs/eleven-agents/libraries/java-script)

انتخاب این مرحله باید با آزمایش ثابت کند می‌توان مجوز، سقف هزینه، لغو نشست و حذف خصوصی را مثل مسیر اصلی رعایت کرد. Signed URL یا agent ID به‌تنهایی این الزامات را برقرار نمی‌کنند. [احراز هویت Agent](https://elevenlabs.io/docs/eleven-agents/customization/authentication)، [Custom LLM](https://elevenlabs.io/docs/eleven-agents/customization/llm/custom-llm)

## ماتریس پذیرش اجباری

| گروه | سناریو و نتیجه مورد انتظار |
|---|---|
| واقعی‌بودن صوت | fixture قراردادی و حداقل PoC ElevenLabs محدود؛ player byteهای واقعی دریافت کند. synthetic test جای آزمون صدای فارسی/میکروفن واقعی معرفی نشود |
| رفتار Send | شروع میکروفن، دریافت partial/final، تغییر حالت یا replay، generation AI جدید نسازد؛ Send یک بار و با idempotency عمل کند |
| هم‌زمانی متن/صوت | پاسخ متنی معتبر و صوت متن متناظر؛ نبود timing پخش را نشکند؛ mapping فارسی/normalization تست شود |
| حفظ و بازیابی | ذخیره AI، گفتگوی کامل opt-in، نوبت منتخب و snapshot تازه؛ close/logout/login مجدد؛ فایل و متن همان مالک بازیابی شوند؛ متن کل رشته و محدوده صوت مشخص باشند |
| ادعای کامل‌بودن | عدم ضبط اول جلسه، پاسخ متنی فاقد audio، interruption، chunk ناقص و شکست provider درست برچسب بخورند؛ هیچ صوتِ ساخته‌شده جای ضبط اصلی ننشیند |
| idempotency | دو save هم‌زمان، acknowledgement گمشده، POST تکراری و payload متفاوت؛ یک asset برای همان snapshot و 409 برای تعارض |
| رقابت حذف/ذخیره | حذف حین finalize یا webhook دیررس، asset را resurrect نکند؛ فایل orphan پاک شود و job حذف در cascade باقی بماند |
| مجوز | کاربر دیگر، Owner غیرمالک، پروژه دیگر، عضویت لغوشده، خبر withdrawn، UUID حدسی و asset key خارجی؛ بدون متن/byte یا خطای افشاگر |

| امنیت انتقال | Origin نامعتبر، ticket تکراری/منقضی، CSRF، frame حجیم/سریع/نامرتب، sample rate جعلی، نام فایل و MIME غیرمعتبر رد شوند |
| هزینه | رزرو هم‌زمان LLM/STT/TTS، تغییر روز، اتمام سهمیه و provider timeout؛ aggregate واحد، بدون دوباره‌شماری و آزادسازی مبهم |
| replay و download | پخش/ذخیره/دانلود فایل موجود هزینه TTS و درخواست LLM اضافه نکند؛ تغییر voice یا تولید صوت متن قدیمی تأیید تازه بخواهد |
| storage | دیسک پر، key ناموجود/اشتباه، فایل دست‌کاری‌شده، Range و rollback؛ بدون plaintext fallback و موفقیت کاذب |
| حذف | حذف صوت مستقل از متن؛ unsave با فایل مرتبط بدون رضایت 409 و با تأیید حذف هماهنگ؛ حذف گفتگو/خبر/پروژه/کاربر، stale URL، نسخه فایل و cache؛ انکار دسترسی فوری و پاکسازی قابل تأیید |

## ورودی‌های قابل تنظیم هنگام شروع توسعه

| تصمیم | پیشنهاد آغازین |
|---|---|
| دامنه اصلی دکمه | پاسخ AI پیش‌فرض؛ گفتگوی کامل انتخاب صریح و قابل استفاده از همان نسخه اول |
| ذخیره متن همراه صوت | الزامی برای اتصال منابع؛ پیام روشن و تأیید واحد در save |
| تعامل | بازبینی و Send در نسخه اول؛ مکالمه پیوسته opt-in در مرحله بعد |
| صدا و زبان | فارسی نخستین معیار کیفیت؛ یک voice تأییدشده برای هر زبان، سپس انتخاب از allowlist |
| مدل کم‌تأخیر | پس از PoC endpoint؛ اختلاف v3/v4 حل و نتیجه نسخه‌دار ثبت شود |
| فایل و محل نگهداری | storage خصوصی رمزگذاری‌شده مستقل؛ codec/format بر اساس ماتریس واقعی مرورگر |
| نگهداری | فایل ذخیره‌شده تا حذف کاربر یا سیاست مصوب Owner؛ staging کوتاه‌عمر؛ retention provider جدا و مستند |
| هزینه | قیمت/واحد واقعی plan با تاریخ تأیید و سقف پایلوت؛ اعداد ثابت تبلیغاتی در کد استفاده نشوند |

این تصمیم‌ها پیش‌فرض‌های پیشنهادی‌اند تا توسعه متوقف نماند؛ اطلاعات حساب/voice/region و تعرفه هنگام اتصال از تنظیمات امن وارد می‌شوند. رمز/کلید از پیام کاربر یا فایل commitشده دریافت نشود.

## تعریف تحویل و گزارش شواهد

گزارش پذیرش آینده باید نسخه SDK/model/endpoint، نتایج کیفیت فارسی و مرورگرهای واقعی، نتایج تست قراردادی/SQL، محدودیت‌های باقی‌مانده، منبع قیمت و اثر هزینه، سیاست نگهداری/حذف و release receipt را ثبت کند. محتوای خصوصی نمونه، key، صوت کاربر واقعی یا transcript واقعی وارد گزارش مخزن نشوند.

فعال‌سازی محدود پس از پذیرش مرحله اول، نظارت هزینه و آزمون kill switch انجام شود. صرف نصب SDK، دریافت صوت روی یک دستگاه، یا موفقیت mockها تعریف تحویل کامل نیست.
