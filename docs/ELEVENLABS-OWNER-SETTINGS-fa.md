# تنظیمات صوت مالک — نسخه ۳٫۵۰٫۰

## مسیر و کارکرد

در بک‌آفیس Admin، صفحه Settings، بخش «تنظیمات ElevenLabs» قرار دارد. این
بخش فقط برای Owner نمایش داده می‌شود و همه endpointهای آن نیز نقش Owner و
نشست معتبر Admin می‌خواهند. تنظیمات برای کل سرویس است، نه یک دستیار خاص.
کادر JSON قدیمی از بخش حساب کاربری حذف شده است.

۱. کلید را در کادر محرمانه وارد کنید. «آزمون اتصال» می‌تواند همان کلید تازه
را پیش از ذخیره بررسی کند؛ آزمون به‌تنهایی کلید را ذخیره نمی‌کند.
۲. «ذخیره کلید» را بزنید. مقدار کلید پس از ذخیره از کادر پاک می‌شود و هرگز
از API خواندنی بازگردانده نمی‌شود. برای جایگزینی، کلید جدید وارد کنید.
۳. صداهای حساب را دریافت یا جست‌وجو کنید؛ صفحه‌بندی برای فهرست‌های بزرگ وجود
دارد. در پروفایل پاسخ، شناسه صدا، نام، مدل، روش انتقال، زبان‌های آزموده‌شده،
هم‌زمان‌سازی متن، حداکثر نویسه و فرهنگ تلفظ انتخاب می‌شوند. تا ۱۲ پروفایل.
۴. تعرفه واقعی حساب، مرجع آن و تاریخ اعتبار را وارد کنید. هزینه صوت با بودجه
AI موجود مشترک است؛ اعداد اولیه، قیمت تضمین‌شده ارائه‌دهنده نیستند. برای
صدای جدید هزینه تولید به‌صورت پیش‌فرض خالی است تا تعرفه حدس‌زده‌شده فعال نشود.
۵. فقط پس از آزمون واقعی STT و TTS، گزینه‌های تأیید آزمون را علامت بزنید.
اتصال و دریافت فهرست، کیفیت یا مجوز تولید صوت را ثابت نمی‌کند. آزمون فهرست
هیچ خبر، گفتار کاربر، ضبط یا نمونه پولی ارسال نمی‌کند.
۶. حالت فعال، گفت‌وگوی پیوسته، سقف هر ضبط، کل نشست و سهمیه روزانه را تعیین و
«ذخیره» را بزنید. بخش نگهداری پیشرفته، ظرفیت هر کاربر/پروژه، اندازه فایل،
مهلت ذخیره موقت و مدت نگهداری فایل‌های صریحاً ذخیره‌شده را نیز دارد.

## امنیت و استقرار

- کلید در SQL، سیاست JSON، Git، گزارش خطا، حساب کاربر یا Google Sheet ثبت
  نمی‌شود. فقط یک فایل AES-256-GCM روی volume خصوصی صوت نگهداری می‌شود.
- مسیر زیرپوشه `credentials/elevenlabs.aead` است. با HKDF یک کلید مستقل از
  کلید رمزگذاری صوت و از همان keyring نسخه‌دار مشتق می‌شود. پوشه 0700 و فایل
  0600، nonce تصادفی، AAD ثابتِ هدف‌دار، نوشتن atomic و fsync اجرا می‌شوند.
  keyring باید جدا از backup رمزگذاری‌شده نگهداری شود؛ کلیدهای نسخه قبلی تا
  پایان re-encryption نباید حذف شوند. keyring داخل مرورگر قابل ویرایش نیست.
- worker و gateway در هر درخواست کلید جدید را می‌خوانند؛ restart لازم نیست.
  تا پیش از ثبت کلید مالک، تنظیمات قدیمی محیط/فایل سرور سازگار می‌مانند.
  حذف کلید، tombstone رمزگذاری‌شده می‌گذارد؛ کلید قدیمی سرور خودکار فعال نمی‌شود.
- چرخش کلید، تأیید قابلیت‌های حساب قبلی را به حساب تازه منتقل نمی‌کند. تولید
  جدید تا تأیید دوباره و ذخیره policy متوقف می‌شود. policy به revision کلید
  متصل است. فرم قدیمی نمی‌تواند کلید یا تأیید جدید مالک دیگر را overwrite کند.
- حذف کلید، فایل‌های صوتی ذخیره‌شده را حذف نمی‌کند. پخش آن‌ها تماس TTS تازه
  ندارد. نگهداری محلی مستقل از نگهداری ارائه‌دهنده است.
- درخواست بررسی تنها به `https://api.elevenlabs.io` ارسال می‌شود؛ redirect،
  proxy محیط و retry خودکار غیرفعال‌اند. پاسخ محدود، timeout محدود و قفل مشترک
  پایگاه داده جلوی آزمون‌های هم‌زمان می‌گیرد. پیام خام ارائه‌دهنده نمایش داده نمی‌شود.
- audit فقط اقدام ذخیره/حذف و انجام آزمون بدون صوت را ثبت می‌کند؛ نه کلید یا
  پاسخ خام. تغییرات CSRF دارند. endpointهای خواندنی هم مقدار کلید را ندارند.
- schema جدید لازم نیست. keyring و volume خصوصی صوت از قابلیت موجود استفاده
  می‌شوند. feature flag سرور خاموش را فرم UI خودسرانه روشن نمی‌کند.

## API

- `GET /admin/api/news-voice/policy`: سیاست و وضعیت بدون رازِ اتصال.
- `PUT /admin/api/news-voice/credential`: `action`, `expected_revision` و فقط
  برای set، `api_key`. delete مقدار کلید نمی‌پذیرد.
- `POST /admin/api/news-voice/connection-check`: کلید اختیاریِ ذخیره‌نشده،
  عبارت جست‌وجوی صدا و page token؛ نتیجه فقط شناسه/نام مدل و صدا و اطلاعات صفحه.
- `PUT /admin/api/news-voice/policy`: فرم تایپ‌شده؛ برای فعال‌سازی با کلید مالک،
  هدر `X-Voice-Credential-Revision` باید با آخرین revision برابر باشد.

کلید به مجوز خواندن Models/Voices برای آزمون فهرست و مجوز STT/TTS برای استفاده
واقعی نیاز دارد. IP allowlist و محدودیت اعتبار حساب نیز باید مناسب باشند.
نمایش مدل‌های سازگار در برنامه به معنی فعال‌بودن همه آن‌ها در حساب نیست.
حالت zero-retention فقط برای حسابی که ElevenLabs پشتیبانی کند قابل استفاده است؛
برنامه از دریافت هشدارِ عدم اعمال آن عبور نمی‌کند. هزینه‌های قطعی تابع صورتحساب
ارائه‌دهنده‌اند و ledger موجود تا reconciliation رزرو محافظه‌کارانه را حفظ می‌کند.

## پذیرش

آزمون unit برای رمزگذاری، مجوز فایل، دست‌کاری، symlink، چرخش keyring، شکست نوشتن،
حذف بدون fallback، مالک‌بودن، خطای بدون راز، revision و قرارداد فهرست وجود دارد.
آزمون مرورگری الزام‌آور در gate ایزوله اضافه شده: login واقعی، CSRF، ذخیره/حذف
کلید، ثبت واقعی policy در SQL، حفظ draft میان هشت زبان و چهار عرض، و accessibility.
همه حساب‌ها، کلیدها و خروجی صوت این آزمون‌ها ساختگی‌اند و شبکه تولید ندارند.
