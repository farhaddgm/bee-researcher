# تکمیل پیگیری‌های تأییدشده — ۱۰ اکتبر ۲۰۲۶

این گزارش به ۲۲ نظر مالک محدود است؛ موارد کنارگذاشته‌شده، «رفع‌شده» محسوب نمی‌شوند. زمان فنی رسیدها UTC است؛ تاریخ گزارش مطابق منطقهٔ زمانی کاربر، Europe/Stockholm، است.

## اصلاحات و شواهد پیش از انتشار

- **اجرای رهاشدهٔ داتین:** اجرای ۱۵:۳۸ UTC قبل از شروع مجدد فرایند در ۱۵:۵۴ باقی مانده و اجرای بعدی موفق بوده است. وضعیت، کار فعال واقعی نبوده؛ دلیل خاموش‌شدن فرایند قبلی از لاگ‌های موجود اثبات نشده است. لغو asyncio اکنون پایان صریح ثبت می‌کند. بازیابی شروع سرویس فقط زیر قفل انحصاری انجام می‌شود؛ سن اجرای job به‌تنهایی مجوز تصاحب کار فعال نیست. دفتر هزینه/تلاش و نتیجه حفظ می‌شوند؛ هیچ خبر خودکار دوباره منتشر نمی‌شود. آزمون SQL واقعی حفاظت lease، تعیین تکلیف orphan و حفظ job تازه موفق است. بستن رکورد تولید باید پس از استقرار تأیید شود.
- **معماری رابط ادمین:** قالب ۴۳۰۰خطی به shell و ۸۱ بلوک مرتب JS/CSS جدا شده؛ ترتیب اجرای فعلی و scope سراسری حفظ شده‌اند. HTTP نسخهٔ اجراشونده، فایل‌های محلیِ content-addressed و cache immutable می‌دهد؛ کد/استایل پیش از نمایش بارگیری می‌شود، نه تبدیل delayed inline. registry هر worker پیش از پذیرش HTTP آماده می‌شود. این تفکیک جایگزین ادعای بازنویسی تمام wrapperهای تاریخی نیست؛ حذف semantic لایه‌های باقی‌مانده یک کار مستقلِ هنوز باز است.
- **CSP:** handlerها به data attributeهای غیرقابل‌اجرا و binder با allowlist تبدیل شده‌اند؛ style attributeها به CSS خارجی تبدیل شدند. صفر handler و صفر style attribute در قالب ادمین؛ گیت CI سقف صفر دارد. eval/Function و تضعیف CSP اضافه نشده‌اند. ابزارهای یک‌بارمصرف مهاجرت پس از اجرای موفق حذف شدند تا اجرای دوباره CSS درست را خراب نکند.
- **لاگر:** alphabet به‌تنهایی مانع ارسال secret نیست. view/action/phase/outcome به فهرست داخلی محدود و URL به template مسیر ثبت‌شده تبدیل می‌شود. متن، stack، query، شناسه و رشتهٔ ناشناخته ثبت نمی‌شوند. تست alphanumeric canary و نرخ/اندازهٔ درخواست موفق‌اند. آزمون HTTPS واقعی بعد از استقرار، گزارش عددی بدون لاگ خام می‌سازد.
- **هشدار تازگی:** اخطار و بازیابی به inbox واقعی Owner، یک‌بار برای هر outage، ثبت می‌شوند؛ خوانده‌شدن باعث تکرار نمی‌شود. نشانی شخصی Telegram/ایمیل حدس زده نشده است؛ تحویل بیرون از بک‌آفیس هنوز نیازمند مقصد تأییدشده است. canary به‌وضوح تست برچسب می‌خورد و فقط همان پیام/نشست موقت پاک می‌شود؛ اعلان‌های دیگر خوانده یا حذف نمی‌شوند.
- **تشخیص انتشار:** receipt شکست، مرحله، نوع امن خطا و نیاز rollback را ثبت می‌کند؛ receipt بازیابی سلامت قبلی را جدا می‌سنجد. علت تاریخی rollback قبلی بدون شاهد قطعی ساخته نمی‌شود. migration محدود 0045، backup خصوصی فقط schema Researcher و تأیید least privilege دارد؛ تغییر نقش، رمز یا schema پروژهٔ دیگر ندارد.

## آزمون و کیفیت

- ۶۰۳ تست برنامه شامل حفاظت cleanup/scheduler، هفت تست پیش‌بررسی نقش/head بسته و یک canary عدم افشای ورودی تنظیمات شروع هستند. ۲۵ تست ابزار انتشار، محدودسازی migration، هویت جداگانهٔ بکاپ و mount/مالکیت harness وجود دارند.
- مسیر قدیمیِ پاک‌سازی اجرای بیش از ۲۴ ساعت نیز به قفل انحصاری وابسته شد: سن زیاد دلیل مرگ کار نیست. اگر barrier خاموش یا کار پذیرفته‌شده فعال باشد، هیچ رکوردی failed نمی‌شود؛ دفتر هزینه/تلاش و ارسال‌های نامطمئن دست‌نخورده می‌مانند. آزمون SQL قدیمی اکنون حفاظت اجرای زنده را هم می‌سنجد.
- deferred شدن cleanup نباید خزش معمول را گرسنه کند: scheduler به tick عادی ادامه می‌دهد. تحویل هشدار inbox نیز مانند سایر کارهای runtime زیر lease قرار دارد و هنگام استقرار پذیرفته نمی‌شود.
- اجرای نخست گیت تازه در CI، mount تو‌در‌تو داخل source فقط‌خواندنی و مالکیت root فایل‌های npm را آشکار کرد. وابستگی‌ها اکنون mount هم‌سطح دارند و نصب با UID/GID اجراکننده است؛ آزمون نصبِ تازه بدون وابستگی‌های قبلی نیز اجرا می‌شود. شکست قبلی پنهان یا گیت حذف نشده است.
- آزمون قدیمی migration نسخهٔ head را ثابت روی 0044 فرض می‌کرد و پس از موفقیت گیت‌های UI با 0045 شکست خورد. اکنون head از همان بستهٔ Alembic خوانده می‌شود؛ رد downgrade مخرب و حفظ شناسه‌های دفتر امنیت/مصرف چت، حساب‌ها، پروژه‌ها و خبرها همچنان اجباری‌اند.
- Mypy: صفر خطا در ۷۶ فایل؛ Ruff correctness و Bandit: موفق.
- مرورگر احرازشده: چت، مجوزهای Owner/non-owner، نشست، SQL، support conversation، focus، کلیک فیزیکی Add در هشت اندازه، هشت زبان و axe در دوازده صفحه: موفق. اعلان مرورگر با Notification آزمایشی است، نه اعلان واقعی سیستم‌عامل.
- ارزیابی **واقعی** relevance با OpenAI/gpt-6-luna و هفت حالت مصنوعی: ۷/۷. هیچ خبر/کانالی برای این آزمون ساخته یا منتشر نشد.
- ارزیابی **واقعی** چت OpenAI/gpt-6-luna: ابتدا ایتالیایی به انگلیسی پاسخ داد. نام کامل زبان به دستور افزوده شد و اعتبارسنجی QA ارجاع‌ها را از نثر جدا کرد. پس از اصلاح، ۸/۸ زبان: اعداد ۱۲ و ۴۰٪، ارجاع معتبر، رد instruction داخل گزارش و نساختن تاریخ اعلام‌نشده درست‌اند؛ پاسخ‌ها نیز بازخوانی شدند. سقف محافظه‌کارانهٔ اجرای نهایی ۰٫۰۰۹۶ دلار بود. این benchmark محدود، تضمین صحت همهٔ اخبار آینده یا اعتبار حساب Claude/Gemini نیست.
- خطای connectivity آزمون نخست ناشی از استفادهٔ شبکهٔ backend بدون egress بود، نه خرابی API تولید؛ ابزار QA فقط namespace شبکهٔ تأییدشدهٔ همان Researcher را استفاده می‌کند. هیچ retry پولی خودکار اضافه نشده است.
- خطاهای واضح کاتالوگ در شش زبان، از جمله سقف ساختمانی، نخ/رزوه به‌جای موضوع و نمایش به‌معنای نمایش هنری اصلاح شدند. کاتالوگ ۱۰۱۴ کلید/۸۱۱۳ ورودی، بررسی خودکار پوشش را می‌گذراند. بازبینی کامل توسط زبان مادری انجام نشده؛ ارسال کامل کاتالوگ برای بازبینی خارجی بدون اجازهٔ صریح، متوقف مانده است.

## حدودی که نباید به‌اشتباه بسته اعلام شوند

۱. پذیرش انسانی screen reader و اعلان بومی سیستم‌عاملِ کاربر؛ آزمون headless جای آن نیست.
۲. طبیعی‌بودن همهٔ متن‌های هشت زبان؛ اصلاح موارد کشف‌شده و پوشش خودکار معادل بازبینی کامل نیست.
۳. فعال‌سازی تجاری Claude/Gemini و سیاست پروژه/حساب چت؛ نیازمند کلید امن، مدل/قیمت بررسی‌شده و اجازهٔ Owner است. قابلیت فعلاً پیش‌فرض خاموش است و مطالعهٔ خبر مستقل کار می‌کند.
۴. مقصد بیرونیِ تأییدشده برای هشدار Owner؛ inbox قابل آزمودن است ولی Telegram/ایمیل نامعلوم نیست.
۵. حذف تمام بازترسیم‌ها/wrapperهای تاریخی؛ تفکیک فایل و تحویل خارجی انجام شده، بازنویسی کامل معماری ادعا نمی‌شود.

## موارد خارج از دامنه طبق دستور مالک

هشت منبع مختل، بار چت، بازیابی حریم خصوصی بکاپ چت، CVEهای تصویر پایه، استفادهٔ واقعی Contenter، بدهی امنیتی Contenter، WhatsApp، MFA و همهٔ ایده‌های تازهٔ محصول بدون اقدام باقی می‌مانند. وضعیت آن‌ها کنارگذاشته‌شده است، نه تکمیل‌شده.

## مانع شروع کانتینر که پیش از استقرار کشف شد

پس از ادغام نخست، بررسی فرمان واقعی start-service نشان داد پیش‌بررسی امنیتی هنوز revision را ثابت روی 0044 می‌خواست؛ fixtureهای UI فرمان شروع را override می‌کردند و این نقص را نمی‌دیدند. آن تصویر روی سرور مستقر نشد. پیش‌بررسی اکنون head را از مهاجرت‌های همان بسته می‌خواند، تمام ۱۲ مجوز جدول‌های چت را جداگانه می‌سنجد و همچنان superuser/DDL/ویرایش دفتر امنیت را رد می‌کند. گیت پذیرش، CMD واقعی تصویر را با هویت‌های کم‌اختیار PostgreSQL و Redis و پیش‌نیازهای ساختگی OAuth در حالت production اجرا می‌کند. برگشت به 3.39 فقط پس از پیش‌بررسی نقش توسط بستهٔ جدید و با حفظ کنترل OAuth، بدون downgrade اجرا می‌شود. digest گزارش‌شده اکنون digest رجیستری است، نه digest متفاوت تنظیمات تصویر.

خطای validation تنظیمات شروع نیز دیگر inputهای خام را چاپ نمی‌کند؛ آزمون canary شامل password واقعی‌نما نبود افشای متن محرمانه را می‌سنجد. هشدار legacy مربوط به path separator در Alembic با گزینهٔ صریح os رفع شد.

بکاپ محدودِ نخست قبل از migration متوقف شد: migrator روی دو جدول تاریخی SELECT نداشت؛ هیچ جدول حذف‌شده از بکاپ یا مجوز تازه‌ای جایگزین این نقص نشد. بکاپ اکنون با نقش runtime موجود که روی همهٔ جدول‌های همان schema اجازهٔ خواندن دارد تهیه می‌شود، DDL همچنان با migrator مستقل انجام می‌شود. همسانی host/database/port و نقش محدود پیش از هر عملیات بررسی می‌شوند؛ نقش، رمز یا مجوز پروژهٔ دیگر تغییر نمی‌کند.

فایل بکاپ واقعی پیش از migration روی دیسک fsync می‌شود؛ گزینهٔ no-sync فقط در آزمون دورریختنیِ /dev/null کاربرد دارد و در فرمان بکاپ تولید استفاده نشده است.

رسید استقرار و وضعیت جاری Google Sheet باید پس از تأیید نسخه/commit/digest واقعی به‌روزرسانی شوند. سبزشدن تست محلی به معنی deploy نیست.
