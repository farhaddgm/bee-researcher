# نتیجهٔ پیاده‌سازی و آزمون زمینهٔ کسب‌وکار — 3.37.0

تاریخ: ۲۰۲۶-۱۰-۰۶ · شاخه: `codex/contenter-business-integration`

## نتیجه

استفادهٔ اختیاری، پروژه‌محور و تأییدشده از کسب‌وکار محلی یا Contenter در تحلیل Researcher پیاده‌سازی شد. این مرحله پس از تأیید جداگانهٔ مالک انجام شده است. اتصال و همگام‌سازی همچنان فقط‌خواندنی‌اند و هیچ پروژه‌ای را خودکار فعال نمی‌کنند. در Contenter، این مرحله تغییر تازه‌ای نسبت به API اتصال قبلی ایجاد نکرده است.

شرح رفتار، محدودیت‌ها و راه‌اندازی: [سند قابلیت](RESEARCH-CONTEXT-fa.md).

### سناریوهای SQL تازه

پیش‌نمایش بدون تغییر خبر/گزارش/کانال؛ یک‌بارمصرف و وابسته‌بودن به کاربر و پروژه؛ رد تأیید پس از تغییر Topic؛ امتیاز تجاری مستقل؛ آزمایش بدون تغییر انتشار؛ اجرای زنده با هر دو شرط؛ حفظ سیاست زنده هنگام آزمایش پیشنهاد تازه؛ هش تمام متن؛ عدم fallback پس از تغییر کسب‌وکار محلی؛ نسخهٔ ثابت Contenter در مقابل نسخهٔ sync جدید؛ کنارگذاشتن واقعیت لغوشده؛ پنهان‌شدن brief پس از لغو دسترسی؛ باطل‌شدن نسل پس از تعویض پیوند؛ منع activation زنده بدون نمونهٔ ارزیابی‌شده.

تولید گزارش با حقایق خصوصیِ حذف‌شده و زبان فارسی آزموده شد. گزارش دارای provenance قدیمی در مرحلهٔ نهایی انتشار رد، سپس بازتولید شد. یک تحویل **مصنوعی بدون شبکه** انجام شد و تکرار آن ارسال دوم ایجاد نکرد. هیچ پیام واقعی تلگرام فرستاده نشد.

### سناریوهای مرورگر

شرطی‌بودن فیلدها، consent صریح، خاموش‌بودن افشای عمومی به‌صورت پیش‌فرض، escape نام کسب‌وکار دارای HTML، اعتبارزدایی پیش‌نمایش پس از ویرایش، رد activation زنده بدون ارزیابی، ذخیرهٔ واقعی shadow از طریق HTTP، بسته‌شدن مودال هنگام تغییر پروژه، رفتار Escape/focus، مجوز واقعی viewer/editor و منع دسترسی پروژهٔ دیگر بررسی شدند. راهنماهای i از کنترلر مشترک بک‌آفیس استفاده می‌کنند؛ متن، bounds و Escape آن‌ها نیز در ماتریس قابلیت جدید بررسی می‌شوند.

رگرسیون عمومی علاوه بر اندازهٔ صفحات، دکمه‌های افزودن رسانه/موضوع، sidebar کوچک‌شده، avatar/menu، کارت‌ها، skeleton، Support، فرم‌های dark، جدول خالی، tooltip، toast و نه تنظیم reader را بررسی کرد.

## مشکل ابزار آزمون که اصلاح شد

آزمون قدیمی `verify_product_reliability.py` در DB دارای پروفایل موجود، ابتدا به برخورد شناسهٔ fixture برخورد کرد: پروفایل‌های legacy/backoffice شناسهٔ عددی صریح دارند و sequence لزوماً جلو نرفته است. fixture به تخصیص صریح سازگار با دادهٔ آزمایشی تغییر کرد و بازاجرای کامل موفق شد. خطا نادیده گرفته یا به skip موفق تبدیل نشد؛ این اصلاحِ fixture، ادعای اصلاح تمام حالت‌های هم‌زمانی شناسه در کد قدیمی نیست.

## مرز نتیجه

- PostgreSQL، Redis و API فقط در شبکهٔ داخلی Docker با داده و حساب‌های مصنوعی اجرا شدند؛ URL عمومی، DB واقعی، زمان‌بندی واقعی و پروژهٔ واقعی تغییر نکردند.
- مدل کنترل‌شدهٔ آزمون جای provider واقعی را گرفت؛ دقت معنایی مدل، کیفیت ترجمهٔ واقعی و اعتبار حساب AI با این آزمون‌ها ثابت نمی‌شوند. هیچ کلید واقعی یا هزینهٔ AI مصرف نشد.
- CI برای دو آزمون تازه الزام‌آور شده، ولی این گزارش نتیجهٔ اجرای محلی است؛ ادعای اجرای GitHub Actions، push یا deploy نیست.
- نسخهٔ 3.37.0 در کد آماده شده است. انتشار production و فعال‌سازی زمینه برای پروژه‌های واقعی انجام نشده‌اند. نسخهٔ زنده در زمان شروع بررسی 3.36.0 بود.
- آزمون این قابلیت به معنی رفع همهٔ بدهی‌های تاریخی محصول یا تأیید طبیعی‌بودن ترجمه‌ها توسط بازبین بومی نیست.

## بازاجرای آزمون

در `src/market_intelligence` و فقط DB `assistant_test`، محیط `test`، scheduler/polling خاموش و بدون اعتبارنامهٔ واقعی AI/Telegram:

```sh
alembic upgrade head
python -m unittest discover -s tests -q
mypy app --ignore-missing-imports
ruff check --config ruff.toml app tests
python scripts/check_csp_inline_budget.py
python scripts/check_i18n_catalog.py
python scripts/verify_research_context_sql.py
python scripts/verify_media_pipeline.py
python scripts/verify_product_reliability.py
npm ci --ignore-scripts
npm run admin:research-context:e2e
npm run ui:e2e
```

دو آزمون مرورگر به `BEE_ADMIN_URL` و اعتبارنامهٔ مصنوعی owner نیاز دارند؛ رگرسیون عمومی `BEE_USER_URL` هم می‌خواهد. آزمون SQL تازه برای حالت Contenter نشانی HTTPS و توکن **مصنوعی** پیکربندی‌شده می‌خواهد، ولی remote snapshot را در DB آزمایشی می‌سازد و درخواست شبکهٔ Contenter ندارد. برای آزمون واقعی خود اتصال HTTPS، از دستورهای گزارش مرحلهٔ اول استفاده کنید. اجرای چند آزمونِ دارای fixture عددی روی یک DB را هم‌زمان نکنید؛ DBها را جدا کنید یا آن آزمون‌ها را به‌ترتیب اجرا کنید.
