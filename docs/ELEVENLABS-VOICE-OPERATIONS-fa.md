# راه‌اندازی و پذیرش صوت در Bee Researcher

راهنمای جاری در ۲۲ اکتبر ۲۰۲۶ بازبینی شد. schema صوت `0049_reader_voice` است و schema کل برنامه تا `0052_analysis_lenses` پیش رفته است. اتصال اصلی Scribe Realtime → مدل‌های موجود Bee → ElevenLabs TTS است. ElevenAgents و Custom LLM مرحله اختیاری جدا هستند.

کلید رمزگذاری‌شدهٔ Owner موجود و با API رسمی بررسی شده است؛ طرح حساب Free است و کاتالوگ مدل‌ها و صداها قابل خواندن است. این بررسی فقط metadata بود؛ آزمون صوت یا اثبات Zero Retention نیست. مالک در ۲۲ اکتبر صریحاً خواست الزام Zero Retention حفظ شود و فعال‌سازی تا فراهم‌شدن حساب واجد شرایط منتظر بماند. بنابراین صوت خاموش است؛ الزام حریم خصوصی برداشته نشده، صدای تأییدشده یا تأیید نگهداری ساختگی ثبت نشده و دادهٔ صوتی خصوصی برای آزمون ارسال نشده است.

در Settings → ElevenLabs، چک‌لیست کلید، حفاظت داده، تعرفه، آزمون تشخیص گفتار، صدای تأییدشده و فعال‌سازی ذخیره‌شده جداست. «بررسی طرح حساب» و «بررسی اتصال» هیچ صوتی تولید نمی‌کنند. اعتبار کلید به‌معنای آمادگی برای فعال‌سازی نیست. بررسی قیمت عمومی در ۲۲ اکتبر با [صفحهٔ رسمی API](https://elevenlabs.io/pricing/api) انجام شد؛ نرخ قراردادی حساب تأیید نشده است. طبق [راهنمای رسمی Zero Retention](https://elevenlabs.io/docs/eleven-api/resources/zero-retention-mode)، مجوز حساب و درخواست بدون نگهداری باید جدا تأیید شوند.

پس از فراهم‌شدن طرح واجد شرایط: ابتدا مجوز Zero Retention و پشتیبانی endpointهای مورد استفاده تأیید شود؛ سپس با عبارت ساختگی، نه محتوای مشتری، آزمون STT/TTS و نبود صوت در history بررسی شود؛ مرجع شواهد و صدای آزموده‌شده در تنظیمات ذخیره شوند؛ تعرفه و سقف هزینه تأیید شوند و تنها سپس Owner صوت را فعال کند. ارتقای اشتراک یا خرید طرح توسط این تحویل انجام نمی‌شود.

## تنظیمات امن سرور

تمام نام‌ها پیشوند `MARKET_INTELLIGENCE_` دارند:

| متغیر | کاربرد |
|---|---|
| `NEWS_VOICE_ENABLED` | کلید توقف سرور؛ پیش‌فرض false |
| `ELEVENLABS_API_KEY_FILE` | فایل secret با مجوز 0600، حداکثر 512 بایت، بدون symlink؛ mount فقط خواندنی |
| `ELEVENLABS_API_KEY` | جایگزین SecretStr در محیط سرور؛ در مرورگر و Owner JSON قرار نگیرد |
| `NEWS_VOICE_KEYRING_FILE` | فایل مستقل کلید رمزگذاری صوت، مجوز 0600، mount فقط خواندنی |
| `NEWS_VOICE_STORAGE_PATH` | volume مستقل صوت، مالک UID/GID 10002، مجوز 0700، قابل نوشتن برای Researcher |

API key سرویس و کلید AES ذخیره صوت دو secret متفاوت‌اند. کلید Report، فایل‌های Report یا volume مشترک آن برای صوت استفاده نشوند. محتوای کلید در PR، لاگ، پیام یا receipt درج نشود. secret account فقط اجازه STT/TTS مورد نیاز داشته باشد.

ساختار keyring: `active` نام کلید فعال و `keys` نگاشت نام‌های ۱ تا ۳۲ کاراکتری به کلیدهای تصادفی ۳۲ بایتی base64 است. هنگام rotation، کلیدهای قبلی برای خواندن فایل‌های موجود حفظ شوند. backup رمزگذاری‌شده keyring و volume، همراه با آزمون بازیابی، پیش از فعال‌سازی لازم است. فایل‌ها با AES-GCM و AAD شامل کاربر، پروژه و asset رمزگذاری می‌شوند.

## آزمون واقعی حساب

ابزار `scripts/verify_elevenlabs_account.py` فقط متن مصنوعی کوتاه را صوت می‌کند و همان PCM را به Scribe می‌دهد. بدون secret معتبر درخواست شبکه ندارد. نمونه قابل تنظیم:

```sh
python scripts/verify_elevenlabs_account.py \
  --voice-id APPROVED_VOICE_ID --model eleven_v3 --transport http \
  --language fa --usd-per-1000-chars ACCOUNT_VERIFIED_RATE \
  --timing --confirm-paid-sample
```

این فرمان هزینه STT/TTS دارد و باید داخل پیکربندی امن همان Researcher با سقف پایلوت محدود اجرا شود. خروجی فقط metadata قابلیت و زمان‌بندی است؛ transcript یا key چاپ نمی‌شود. نتیجه ابزار جای ارزیابی انسانی تلفظ فارسی، عدد/تاریخ، نام شرکت، متن مختلط و آزمایش دستگاه واقعی را نمی‌گیرد. برای انگلیسی آزمون جدا و برای دیگر زبان‌ها بررسی متناسب لازم است.

مستند مرجع TTD هنوز مدل‌های v3 را نام می‌برد؛ راهنمای عمومی جدیدتر به v4 اشاره می‌کند. اجازه v4 در policy فقط با transport TTD و تأیید واقعی account/endpoint است. endpoint قدیمی TTS WebSocket برای v3/v4 استفاده نمی‌شود. مدل HTTP این نسخه `eleven_v3` است. [قرارداد TTD](https://elevenlabs.io/docs/api-reference/text-to-dialogue/ttd-websocket)، [مدل‌ها](https://elevenlabs.io/docs/overview/models)

## فعال‌سازی Owner

در Admin → Account، پنل سیاست صوت برای Owner قابل دسترسی است. ابتدا policy غیرفعال بماند. شناسه صدای مجاز، زبان‌های آزموده، مدل/transport، قیمت STT به دلار/دقیقه، TTS به دلار/۱۰۰۰ کاراکتر، ضریب keyterms و مرجع/انقضای تعرفه واقعی وارد شوند. مقادیر پیش‌فرض تست تعرفه حساب نیستند. `stt_verified` و `voices[].verified` تنها پس از ثبت شواهد واقعی فعال شوند.

بعد از آماده‌بودن volume/secrets و آزمون‌ها، کلید توقف سرور و policy فعال شوند. نبود کلید، نبود keyring، policy غیرفعال، voice تأییدنشده یا تعرفه منقضی، درخواست پولی را رد می‌کند. `require_zero_retention` فقط برای حسابی استفاده شود که این قابلیت را واقعاً پشتیبانی می‌کند؛ هشدار Scribe در این حالت موجب قطع اتصال است. [Zero retention](https://elevenlabs.io/docs/overview/administration/data-retention)

رزرو هزینه LLM/STT/TTS با یک قفل مشترک و سقف روزانه کاربر در همه پروژه‌ها انجام می‌شود. موفقیت provider ابتدا «برآورد» است؛ timeout مبهم رزرو را آزاد نمی‌کند. Owner می‌تواند از `GET /admin/api/news-voice/usage` موارد باز را ببیند و با `POST /admin/api/news-voice/usage/{id}/reconcile`، مبلغ واقعی و مرجع صورتحساب را ثبت کند. این API transcript و حساب دیگران را برنمی‌گرداند؛ تغییر دارای audit است.

## رفتار فایل و پاکسازی

«ذخیره صوت» فایل WAV واقعیِ PCM مونو ۱۶kHz را ذخیره می‌کند. انتخاب پیش‌فرض صوت AI است؛ انتخاب صدای کاربر و AI فقط از ضبطی استفاده می‌کند که کاربر پیش از ارسال صوت اجازه نگهداری موقت آن را داده است. متن شناخته‌شده و سؤال ویرایش‌شده جدا در manifest ثبت می‌شوند. فایل جدید snapshot محدوده و نوبت‌های منتخب است؛ نوبت‌های بعدی خودکار به آن اضافه نمی‌شوند.

ذخیره صوت، متن کل گفتگو را هم در حافظه خصوصی همان پروژه حفظ می‌کند و رابط این موضوع را پیش از تأیید اعلام می‌کند. فایل‌های ناقص یا قطع‌شده به رضایت صریح برای نسخه ناقص نیاز دارند. پخش مجدد، تنظیم سرعت، bookmark، clip، دانلود و ذخیره فایل موجود درخواست TTS تازه ندارند. bookmark می‌تواند پیش‌نویس اقدام بسازد؛ اقدام بدون تأیید کاربر ذخیره نمی‌شود.

فایل موقت حداکثر ۱۵ دقیقه عمر دارد؛ پذیرش ذخیره در آستانه انقضا فقط به مدت lease کوتاه همان job آن را نگه می‌دارد. بستن پنجره/logout/انقضای گفتگو ذخیره‌نشده، دسترسی را قطع می‌کند. فایل ذخیره‌شده تا حذف کاربر یا retention سیاست Owner باقی می‌ماند. حذف صوت مستقل از متن است؛ خارج‌کردن متن از حافظه با صوت مرتبط بدون تأیید حذف فایل، 409 می‌دهد.

Outbox بدون FK با trigger پایگاه‌داده، حذف byteها را حتی پس از cascade کاربر/خبر/پروژه پیگیری می‌کند. worker پاکسازی هر ۱۵ ثانیه اجرا می‌شود؛ خطای storage باعث موفقیت کاذب حذف فیزیکی نمی‌شود. deny دسترسی با tombstone فوری است. staging و فایل‌های orphan پس از crash پاکسازی می‌شوند. migration additive است؛ rollback برنامه schema، فایل یا ledger را حذف نمی‌کند و guard پایگاه‌داده برای نسخه قدیمی هم پابرجاست.

## مرورگر و شواهد

AudioWorklet مسیر ترجیحی دریافت PCM است. اگر بارگذاری آن شکست بخورد یا طی ۲ ثانیه کامل نشود، ScriptProcessor در Web Audio با همان resampler و wire format استفاده می‌شود. در محیط Chromium ایزوله فعلی، خود addModule در یک صفحه مستقل هم معلق می‌ماند؛ بنابراین آزمون میکروفن این محیط مسیر جایگزین را پوشش می‌دهد. پشتیبانی فیزیکی Worklet، Safari/iOS و کیفیت واقعی حساب هنوز باید با دستگاه و حساب آزموده شوند.

پخش تدریجی PCM از حافظه محدود producer انجام می‌شود؛ متن و صوت به provider دیگری برای LLM منتقل نمی‌شوند. process دیگر، بدون تولید مجدد، از WAV تکمیل‌شده استفاده می‌کند. توقف یا میکروفن، preview/player قبلی را قطع می‌کند. autoplay ناموفق به player دستی می‌رسد. timing فقط در صورت تطابق کامل با متن آماده گفتار نمایش داده می‌شود. بازه‌های پخش گزارش مرورگرند، نه اثبات شنیدن توسط انسان.

گیت‌های مخزن: unit/contract، SQL واقعی، مرورگر synthetic provider، resampling ۱۶/۴۴٫۱/۴۸/۹۶kHz، scope/ACL، Range، idempotency، رقابت بودجه/ذخیره/حذف و regression حافظه، پژوهش، Admin و Report. وضعیت اجرای واقعی هر گیت و release در گزارش پذیرش ثبت شود؛ این سند به‌تنهایی نتیجه آزمون یا رسید انتشار نیست.
